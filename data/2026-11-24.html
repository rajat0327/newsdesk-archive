Nikolay Samokhvalov: The hidden costs of CREATE TEMP TABLE: catalog bloat and LWLock:SInvalWrite

Benchmarking transactional workloads in PostgreSQL shows that CTEs achieved 23x the throughput of temporary tables. Frequent temporary table creation causes system catalog bloat and severe contention on LWLock:SInvalWrite locks under concurrent connections.

Why it matters — Temporary table DDL mutates system catalogs and triggers shared invalidation locks across all sessions, making CTEs drastically faster for short-lived transactional logic.

Radim Marek: Your biggest tenant runs someone else's plan

Why it matters — Global table statistics can produce optimal query plans for average tenants while causing expensive full-table scans for large outlier tenants in multi-tenant databases.

Chris van Eijk: could not resize shared memory segment: Postgres in Docker

Diagnoses the cause of shared memory segment allocation failures in Dockerized PostgreSQL deployments. Explains that the failure stems from exhausting Docker's default 64 MB /dev/shm partition rather than host disk space, demonstrating why a 256 MB allocation fell short under parallel query workloads.

Why it matters — PostgreSQL parallel queries use POSIX shared memory mapped to /dev/shm, which defaults to 64 MB in Docker and requires explicit mounting or sizing to avoid runtime crashes.
