Vadim Yatsenko: Zero-Copy I/O for the Shared Storage Daemon: Removing the Last Copy from the WAL Path

In PolarDB, every database commit requires the Write-Ahead Log (WAL) record to reach shared storage, involving data movement from WAL buffers through a shared-storage daemon to the device. This article details how the last data copy in this critical WAL path was eliminated to improve performance.

Why it matters — Optimizing the WAL path by eliminating unnecessary data copies, such as through zero-copy I/O, is a critical technique for enhancing durability and performance in high-throughput database systems.

Vadim Yatsenko: Commit Sequence Number (CSN) MVCC: Lock-Free Snapshot Acquisition

PostgreSQL's Multi-Version Concurrency Control (MVCC) determines row visibility by checking if a writing transaction was committed before a query's snapshot. This article describes Commit Sequence Number (CSN) MVCC, a technique for achieving lock-free snapshot acquisition, improving concurrency.

Why it matters — Implementing Commit Sequence Number (CSN) MVCC enables lock-free snapshot acquisition, a crucial technique for improving concurrency and performance in highly transactional database systems.
